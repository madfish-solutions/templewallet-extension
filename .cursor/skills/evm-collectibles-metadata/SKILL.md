# EVM collectible metadata

- OpenSea batch metadata (`/multichain-collectibles-metadata`) accepts at most 30 JSON refs. The route keys results by contract address and token id, ignoring chain id, so the same pair is sent in a separate request. Fill each of those requests up to 30. Do not send the whole wallet.
- OpenSea account NFTs (`/opensea-collectibles-metadata`) are loaded as one page of 200 items. Do not follow the `next` cursor. A `collection` query limits that page to one known OpenSea collection slug. It names that collection; it does not sample new creators.
- OpenSea requests that receive HTTP 429 are retried up to 3 times. Wait for the `Retry-After` header (seconds, or an HTTP date). Schedule that retry on its own so metadata that already arrived is stored without waiting.
- Switching the collectibles list between a flat list and collections (`viewAsCollections`), or changing the network filter (`filterChain`), cancels the metadata load already in flight, including its OpenSea batch, account page, retries, shared-storefront collection requests, and the on-chain queue. Checked chains are recorded only after that load finishes, so a cancelled load does not skip Goldrush next time. The replacement load waits until the tiles for the new list publish visibility, then those visible NFTs go first.
- Pass the NFTs reported as visible into `loadEvmCollectiblesMetadataAction`. Tiles call `reportEvmCollectibleVisibility` when they enter or leave the viewport. A collapsed collection only mounts its first row. Skip tiles whose preview is already a preferred URL. IPFS previews stay eligible for OpenSea and remain the last resort, including `https://ipfs.covalenthq.com/ipfs/<cid>` and Covalent image proxies of that URL. Goldrush `i.seadn.io/gae/{id}` image URLs (including Covalent proxies of them) are rewritten to `https://lh3.googleusercontent.com/{id}`, keeping a requested width as `=s{width}`, because `i.seadn.io` no longer resolves. Other `i.seadn.io` URLs, such as `/gcs/files/`, cannot be rewritten and stay eligible for OpenSea. If that list is shorter than 30, fill the spare slots from stored collectibles, keeping the visible refs first. Take one nameless shared-storefront token per creator address before other previews, so those slots discover a new collection for each creator. Do not open another request once the batches already started are full. Store account-page NFTs directly so their previews use OpenSea CDN URLs.
- On-chain metadata is loaded only for NFTs that are on screen and still have no metadata after Goldrush and OpenSea. Read 8 of those at a time, then another batch every 4 seconds while more visible NFTs remain. A later scroll loads an NFT that was off screen during the first scan. NFTs that stay off screen are not read on-chain. `putEvmCollectiblesMetadataAction` must run after `processLoadedEvmCollectiblesMetadataAction`. The Goldrush reducer replaces stored image URLs.
- Store a non-image file on `artifactUrl`: video, audio, a 3D model (`glb`, `gltf`, `usdz`), or HTML. OpenSea does not snapshot audio, models, or HTML, so the thumbnail stays a separate image when one exists. A video on `seadn.io` (`raw`, `raw2`, `i`, `i2`, `i2c`, extensions `mp4`, `webm`, `mov`, `m4v`, `ogv`) gets a still preview at `i2.seadn.io` with `?frame-time=1&w=500`. The file itself stays `artifactUrl`. That frame is the first preview even when another cover image is stored, so a grid thumbnail does not wait for an animated cover or the media file. Apply that rewrite when building previews so an already stored video URL is not passed to `<img>`. An extensionless URL is not a thumbnail when another image field in the same response is audio, video, a model, or HTML. Keep that OpenSea record when `artifactUrl` is on an OpenSea CDN host, even with no cover image. The detail page plays `artifactUrl` through the same player switch as Tezos (`CollectiblePageMedia`): video, audio, glTF/GLB, and HTML. A video shows that still until the file can play. Audio shows the play controls immediately and starts playback when the file is ready. With no cover, the poster is the music icon. USDZ stays on the still image. HTML is a sandboxed iframe with scripts enabled and without the extension origin. If the player fails, show the still image.
- On an Alchemy chain, the collectibles list is the Alchemy inventory, not the Goldrush slug map. `getNFTsForOwner` `totalCount` is the number of NFTs that match the query. The home NFTs counter uses that total, minus collectibles the account removed or disabled. It does not follow how many token pages are loaded, so a refresh that keeps the first page does not shrink the counter. Before that owner page is stored, balances of up to 3 of its tokens, from different contracts, are read. Alchemy’s report rates are the prior weight, and each confirmed token adds one. The Alchemy page is replaced by Goldrush collectibles when the chance a reported token is owned falls below one half. Goldrush is checked with its own rates. A token the sample proves unowned is left out even when the page stays, and the total and contract count shrink by those tokens. One owned sample does not keep a sample that is mostly unowned. ERC-721 `balanceOf` of 0 counts as unowned when `ownerOf` does not return. A call that does not answer leaves the prior, so the page stays. Owner-contract and owner-NFT requests send `excludeFilters: ['SPAM']`. The client keeps items the response still includes, so showing spam later is a change to that filter. A contract card uses `numDistinctTokensOwned` until OpenSea account-collections names that contract. The NFT page shows that card's image. Its amount is the balance already stored, otherwise the quantity read for that token: the ERC-1155 balance, or 1 when ERC-721 `ownerOf` says this account owns it. That quantity is kept on the loaded token. The client follows that cursor for at most 5 pages of 100. Then one card per collection uses `itemCount` (distinct NFTs this account owns, not the collection supply). `totalQuantity` is the owned quantity and is higher only for an ERC-1155 balance above 1. Token ids are loaded one page at a time. A collection card on screen whose loaded tokens are fewer than its collapsed preview row (four tokens, or the owned count when that is smaller) requests its contracts and follows that cursor for at most 5 pages. Two of those requests run at a time. That is the same request opening the card makes, and a successful response is not requested again this session. An empty page with a `pageKey` is followed. The scan is ignored when `totalCount` changes before any NFT arrives, or when the cursor ends with no NFTs and a positive `totalCount`. A `totalCount` change after NFTs have arrived is kept. When that card is an OpenSea collection and the scan is unusable, fails, or returns no NFT of that collection, one page of `/opensea/by-account` for its slug is requested before the load is finished. Each token on that page keeps the page's collection slug, replacing a different slug already stored for the same token. A cancelled load, or one whose OpenSea request failed, is not remembered, so the card can request it again. Do not follow that page's `next` cursor. A contract card has no OpenSea slug, so it does not make that request. HTTP 429 waits for the `Retry-After` header and tries again, up to 3 times. Chains Alchemy does not support stay on Goldrush. The old metadata load skips Alchemy chains. Search on a chain both Alchemy and OpenSea support calls OpenSea search for that one chain, then keeps the hits the account owns. A query that is a contract address, or that address plus `_` and a token id, also asks Alchemy for the NFTs of that contract on every Alchemy chain, including chains OpenSea does not support. The address alone uses one page. A token id is read from later pages of that contract, up to five, and stops when the token is found. Any other query uses one Alchemy page of contracts already stored for the account: an address prefix of 8 to 39 hex digits selects stored contracts that start with it, and a name of at least three characters selects stored contracts and single-contract collections whose name contains it. A contract that hosts more than one known collection is left out of that page, because the page would mix those collections. Alchemy has no text index, so a token id without a contract stays on OpenSea search and the loaded page. While a search is pending, or after it fails, the list keeps the local filter of the loaded page.
- The collection title is the Goldrush contract name, then a name already stored, then the OpenSea `collection` slug. The slug is what groups a collection that would otherwise be labeled unknown. The collections list is ordered by size, largest first. An unnamed OpenSea Shared Storefront group stays at the bottom. A collection discovered from it takes its size rank among the other collections. OpenSea maps one contract to one collection. As soon as one NFT of that contract has a collection name, copy it onto the nameless NFTs of the same contract that already have a record, and group every other owned NFT of that contract under that name too, including NFTs that do not have their own metadata yet. Do not request OpenSea only to learn that name again. Token ids at or above 2^96 are OpenSea Shared Storefront items: one contract hosts many collections there, so those names stay per NFT. Goldrush's contract name for that contract is not a collection. Do not store it as `name`, do not display it, and do not treat it as the token already being named. Request OpenSea for every shared-storefront token that does not yet have `openseaCollection`, including tokens Goldrush already described and tokens whose preview is already usable. Store `nft.collection` on `openseaCollection` and `name`. Visible tokens stay first in the batch of 30. Spare slots then take one such token per creator, then the other shared-storefront tokens that still have no OpenSea slug, then other previews. Do not open another batch once those batches are full. After one of those NFTs reveals a collection slug, request `/opensea-collectibles-metadata` once this session with `collection` set to that slug (one page, do not follow `next`) when the same creator still has an unnamed token outside the response and still averages more than two owned tokens for each of that creator's collections already seen. Request the highest of those ratios first. A creator with one or two tokens, or whose known collections already average two or fewer tokens, does not get that request. While a collection request is in flight, do not send other nameless tokens of that contract to OpenSea only to learn a name. A preview that is still a last resort stays eligible. A visible NFT with no collection name, and no name to copy from its contract, is included in the OpenSea batch even when its preview is already usable, and that request is remembered for the session. If the OpenSea preview is still a last resort, keep a stored record and copy the slug onto it. When nothing is stored yet, store that OpenSea record, including the last-resort preview, so the collection name and image are kept. A preferred image from the same response stays ahead of an IPFS OpenSea image.
- When a thumbnail fails to load and its URL is not already an OpenSea CDN host (`i2.seadn.io`, `i2c.seadn.io`, `raw.seadn.io`, `raw2.seadn.io`), request OpenSea metadata for that NFT once. A failed OpenSea image does not request OpenSea again. Remember the slug for the session only.
- After a collection card has its Alchemy and OpenSea token ids, every contract on that card is checked together. `eth_getCode` is read for each contract at the same time. When a bytecode has none of the ownership selectors, the proxy destination is taken from the EIP-1167 address in the code, or from the EIP-1967 implementation slot, or from `implementation()` on the EIP-1967 beacon, and `eth_getCode` is read for that contract, for at most two hops. The standard ERC-721 and ERC-1155 reads are used only when that destination still has none of the selectors. One multicall then reads only the methods that are present, across every contract: ERC-721 `balanceOf(account)` and `ownerOf` for each id, ERC-1155 `balanceOfBatch` when it is present, even when `balanceOf(account, id)` is not, and `balanceOf(account, id)` for each id when that selector is present, and `tokensOfOwner(account)` or `walletOfOwner(account)` only when their selectors are present. A list from those methods is kept only when its length equals `balanceOf`. When `tokenOfOwnerByIndex` is present, `balanceOf` is at most 128, and those list methods did not already return that many ids, a second multicall reads indexes 0 through that balance and keeps the list only when its length matches `balanceOf` and no listed id fails `ownerOf`. A token the chain says the account does not own is removed. A token the chain says the account owns is kept even if OpenSea did not list it. Ids the calls did not answer are filled, highest API posterior first, until the owned set reaches `balanceOf`. OpenSea is the strongest API prior, then Alchemy, then Goldrush. Per-token chain proof outranks that prior and outranks the counter. The collection count becomes `balanceOf` when this account has no other collection on that contract. A token OpenSea did not name is placed on that sole collection. If the contract has several of this account's collections, a slug already reported for that token is kept when it is one of those collections. One `by-refs` batch (at most 30) asks OpenSea which collection an owned token with no such slug belongs to.
